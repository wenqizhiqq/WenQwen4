**软件定位**

WenQwen 是一个完全离线的工业 AI 助手，目标是在不联网的工控机上，基于本地 GGUF 大模型和本地资料回答问题。它不做模型训练，也不依赖云端 API，推理、知识检索和对话记忆全部在本机完成，适合设备现场、保密车间等不能联网的场景。

**运行形态**

项目为 .NET 8（net8.0-windows）单工程程序，输出类型是控制台 Exe，仅借用 WinForms 的 MessageBox 做提示。精简后只剩两个源文件：`LocalChatAssistant.cs` 承担入口和全部业务，`ModelLocator.cs` 负责模型定位。启动时设置 UTF-8 控制台编码，打印“正在加载模型”，确认模型可用后加载 GGUF 并进入问答循环。

**模型定位与加载**

默认模型是 `D:\wqz\models\qwen2.5-7b-instruct-1m-q4_k_m.gguf`。若默认路径不存在，ModelLocator 先在各盘浅层目录按同名文件广度搜索，深度 3，跳过 Windows、Program Files、AppData、node_modules 等目录，单盘限 4 秒、总计 10 秒，非系统盘优先；仍找不到则退化为查找文件名含 qwen 的最大 `.gguf`；再失败才弹窗并允许手工输入路径，最终仍不存在则退出。加载参数为上下文 8192、线程数等于 CPU 核数、GpuLayerCount 为 99，但实际引用的是 LLamaSharp 的 CPU 后端，因此只能 CPU 推理。7B Q4_K_M 模型约 4.7GB，运行时内存约 4 到 5GB，加载和生成速度取决于 CPU。

**知识库（RAG）**

程序从当前目录的“资料”文件夹递归读取 txt、md、doc、docx 文件，以 UTF-8 读取全文，每 800 字切块，保存文件名和内容，单个文件出错则跳过。需要指出，doc 和 docx 被当作纯文本读取，真正的二进制文档会乱码或读不到内容，这是当前实现的明显短板。

**问答与推理**

主循环中，输入 exit 退出、clear 清空记忆；输入纯数字且等于上一轮编号时，自动追问“请详细解释：上一问题”；其余输入作为新问题。检索采用分词后的字面命中计分，取分数最高的两个知识块拼入提示词，没有向量化、同义扩展或重排。提示词使用 Qwen 的 `im_start` 模板，包含“只依据资料回答”的系统约束、全部历史与当前问题。推理参数为最大 800 token、温度 0.2，遇到 `im_end`、`User:` 等标记停止，答案逐 token 打印并累积，随后写入内存中的对话历史。

**部署与使用**

把模型放在任意磁盘的浅层目录即可，文件名保持不变；把要学习的文件放进程序运行目录下的“资料”文件夹，启动后会自动加载并列出已学习文件。机器需安装 .NET 8 运行时。首次启动要花数秒到数十秒加载模型，之后按提示输入问题即可。对话只保存在当前进程内，退出即丢失。

**现状与局限**

优点是零联网、部署简单、入口单一；模型缺失能自动跨盘查找，容错比原来好；资料块与历史拼接让回答更贴近本地知识。局限也很明显：检索只是关键词匹配，中文分词粗糙，换个说法就可能漏检；历史无限增长并全部拼进提示词，长对话会变慢甚至超出上下文；知识库每次启动重建，没有持久化；doc/docx 未真正解析；CPU 后端下 7B 模型吞吐有限；控制台交互没有并发和会话管理；工程里仍保留 OpenCvSharp、TorchSharp、Whisper、NAudio 等与现有功能无关的包，可以继续精简。总体看，这是一个可用的本地工业知识问答原型；若要产品化，应优先补向量检索、文档解析、历史裁剪和图形界面。
