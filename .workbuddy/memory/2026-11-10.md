## 环境坑：.ps1 经 Write 工具写入会被加密驱动处理

- 现象：用文件写入类工具创建的 `build.ps1`，磁盘字节为 `ef bb bf ef bf bd 7d 1c ...`（含 88/7d/1c 加密 marker 特征），`powershell.exe -File` 直接报语法错误（ParserError），复制到克隆目录同样是密文。
- 对照：PowerShell 自身 `Set-Content -Encoding UTF8` 写入的 .ps1 保持明文（`ef bb bf 57 72 69 74 65`），1 分钟后仍是明文；`.gitignore` 在磁盘上也是密文（88 7d 1c 开头），但 `git show HEAD:.gitignore` / `git check-ignore` 正常（git 走解密通道）。
- 结论：在本机写 .ps1/.cmd 等脚本文件**必须用 PowerShell 直接 Set-Content 写入并回读校验 BOM 与行数**，不要用通用文件写入工具；改 `.gitignore` 也有同类风险，未提交前不要轻易追加（本次未改 .gitignore，`.workbuddy/` 目前仍是未跟踪状态）。

## 编辑加密态 .gitignore 的安全手法（本次验证成功）

1. 备份：`Copy-Item .gitignore D:\wqz\code\_archive\.gitignore.bak`。
2. 用 `[Console]::OutputEncoding=[Text.Encoding]::UTF8` 包住 `git cat-file -p HEAD:.gitignore` 取明文（否则 PS 5.1 按 GBK 解码成乱码）。
3. `Set-Content -Encoding UTF8` 写回会加 BOM → 用 `UTF8Encoding($false)` + `WriteAllText` 去 BOM，并用 `git hash-object` 与 `git rev-parse HEAD:.gitignore` 比对，**哈希一致**才算无损。
4. 追加内容用 `[System.IO.File]::AppendAllText` + `UTF8Encoding($false)`，注意补结尾换行（否则 git 报 "No newline at end of file"）。
5. 校验：`git diff` 只应出现新增行，不能有整段替换（整段替换说明编码已被破坏）。
6. `cmd.exe` 在 PowerShell 工具里被安全策略禁止，不能用 `cmd /c "git ... > file"` 做字节级重定向。
